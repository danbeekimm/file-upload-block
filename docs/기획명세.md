# 파일 업로드 확장자 차단 — 기획 명세

> 개발 기준 문서입니다. 데이터 모델의 상세 정의는 `schema.sql`을 따르며, 이 문서와 스키마가 다르면 둘 중 하나를 고쳐 항상 일치시킵니다.
> 미결 사항은 [16. 미결 사항](#16-미결-사항)에 모아 두었습니다.

---

## 0. 개요

### 배경과 목적

`exe`, `sh` 같은 실행 파일이 업로드되어 서버에서 실행되거나 다른 사용자에게 배포되면 보안 문제가 생깁니다. 이 과제는 확장자 기반 차단 정책을 관리하는 화면과, 그 정책을 실제 업로드에 강제하는 기능을 구현하고 배포하는 것입니다. 구현만큼이나 **무엇을 고려했고 왜 그렇게 판단했는지**, 그리고 그 과정에서 **AI를 어떻게 활용했는지**를 문서로 남기는 것이 중요합니다.

### 필수 범위

| 구분 | 요구사항 |
|---|---|
| 고정 확장자 | `bat`, `cmd`, `com`, `cpl`, `exe`, `scr`, `js`. 기본값 unCheck. check/uncheck 시 DB 저장, 새로고침 후 유지. 커스텀 영역에는 표시하지 않음 |
| 커스텀 확장자 | 입력 최대 20자. "추가" 시 DB 저장 후 목록 표시. 최대 200개. `X` 클릭 시 삭제. 중복 추가 방지 |
| 업로드 | 정책을 실제 업로드에 적용. 차단 대상은 명확한 사유와 함께 거부. 정상 파일은 저장 |

### 산출물

`README.md`(실행 방법, 테이블 스키마 포함), `CONSIDERATIONS.md`(고려사항과 판단 근거), `PROMPT_LOG.md`(AI 활용 기록), 배포 URL.

### 기술 전제

| 항목 | 선택 |
|---|---|
| 백엔드 | Spring Boot (Java) |
| DB | PostgreSQL 13 이상 |
| 저장소 | S3 (세부 사항은 미결, 16장 참고) |
| 신뢰 목록 | Java enum `TrustedFileType` (DB 테이블 없음, 5-2 참고) |
| 인증 | 도입하지 않음 (12장 참고) |

## 1. 핵심 설계 원칙

**요구사항의 블랙리스트에 화이트리스트를 혼합합니다.** 모든 파일은 아래 세 단계 중 하나로 판정됩니다.

| 단계 | 대상 | 처리 |
|---|---|---|
| 차단 | 블랙리스트 확장자(고정·커스텀), 실행 파일 시그니처, 각종 정책 위반 | 거부 |
| 신뢰 | 신뢰 목록 확장자이면서 시그니처가 일치하고 내용 검사를 통과한 파일 | 저장. 조건부 inline 제공 |
| 비신뢰 | 그 외 전부 | 저장. `application/octet-stream` + `attachment` + `nosniff` |

**판정 규칙**

| 규칙 | 내용 |
|---|---|
| 차단 우선 | 같은 확장자가 블랙리스트와 신뢰 목록에 모두 있으면 블랙리스트가 이깁니다. 예: 커스텀 차단에 `jpg`를 넣으면 jpg 업로드는 거부 |
| 실행 파일 시그니처는 전면 적용 | 신뢰·비신뢰와 무관하게 모든 파일에 적용합니다. 고정 확장자가 모두 unCheck여도 이 검사가 최소 방어선입니다 |
| 신뢰 확장자 불일치는 거부 | 신뢰 목록 확장자인데 시그니처가 맞지 않으면 비신뢰로 낮추지 않고 `CONTENT_MISMATCH`로 거부합니다 |
| MIME은 서버가 판별 | 클라이언트가 보낸 `Content-Type`은 판정에 쓰지 않고, 위변조 신호로 기록만 합니다 |

**검증 책임 분리**

| 계층 | 역할 |
|---|---|
| 클라이언트 | UX. 즉각적인 피드백 |
| 서버 | 강제. 유일하게 믿을 수 있는 판정 |
| DB | 무결성. UNIQUE, CHECK 제약으로 서버 버그가 있어도 잘못된 데이터가 들어가지 않게 함 |

## 2. 업로드 판정 파이프라인

비용이 싼 검사를 앞에, 비싼 검사를 뒤에 둡니다. 요청 단위 검사는 파일 본문을 읽기 전에 끝냅니다.

### 2-1. 요청 단위 (서블릿 필터, 멀티파트 파싱 전)

| 순서 | 검사 | 실패 시 |
|---|---|---|
| 1 | 요청 IP가 차단 중인가 (`ip_block`) | `TEMPORARILY_BLOCKED` (429) |
| 2 | 요청 수 제한 (5분 10회) | `RATE_LIMITED` (429) |
| 3 | 요청 전체 크기 (`Content-Length` ≤ 100MB) | `REQUEST_TOO_LARGE` (413) |
| 4 | 파일 개수 (≤ 10개, 멀티파트 파싱 후) | `TOO_MANY_FILES` (400) |

요청 단위 거부는 `file_upload`에 기록하지 않고 애플리케이션 로그에만 남깁니다.

### 2-2. 파일 단위

한 요청의 파일은 각각 독립적으로 판정하고, 파일별 결과를 돌려주는 **부분 성공** 방식입니다. 판정 시작 시 차단 목록과 정책 버전을 한 번에 읽어 요청 전체에 같은 스냅샷을 적용합니다. 신뢰 목록은 enum이라 조회가 필요 없습니다.

| 순서 | 단계 | 실패 시 사유 코드 |
|---|---|---|
| 1 | 파일명 추출과 저장용 정제 (3-1) | — |
| 2 | 파일명 유효성 (빈 이름, 점만 있음, 255바이트 초과) | `INVALID_FILENAME` |
| 3 | 세그먼트 분해와 비교용 정규화 (3-2, 3-3) | — |
| 4 | 블랙리스트 검사 (마지막 세그먼트 → 중간 세그먼트) | `BLOCKED_EXTENSION`, `BLOCKED_INNER_EXTENSION` |
| 5 | 앞부분 읽기 (8KB) | — |
| 6 | 실행 파일 시그니처 검사 (5-1) | `EXECUTABLE_DETECTED` |
| 7 | 신뢰/비신뢰 분류와 시그니처 일치 확인 (5-2) | `CONTENT_MISMATCH` |
| 8 | 탐지된 형식 기준 크기 검사 (이미지 10MB, 그 외 25MB) | `SIZE_EXCEEDED` |
| 9 | 형식별 내용 검사: 이미지 리렌더링(5-3), PDF(5-4), zip(5-5) | 각 절 참고 |
| 10 | 제공 방식 결정 (`content_type`, `disposition`), 점 파일 이름 재부여 | — |
| 11 | 저장 (UUID 키) 후 DB 기록 | — |

거부된 파일도 사유 코드, 위반 점수, 정책 버전과 함께 `file_upload`에 기록합니다. 저장 성공 후 DB 기록이 실패하면 저장한 객체를 삭제합니다. 서버 디스크의 멀티파트 임시 파일은 판정 결과와 무관하게 요청 종료 시 반드시 삭제합니다.

## 3. 파일명 처리

### 3-1. 저장용 정제

원본 파일명은 가능한 한 바꾸지 않되, 다음은 예외로 반드시 처리합니다.

| 처리 | 이유 |
|---|---|
| 경로 제거 (`/`, `\` 뒤의 마지막 부분만) | 구형 브라우저가 전체 경로를 보내는 경우, 경로 조작 |
| NFC 정규화 | macOS에서 올린 한글 파일명이 자모 분리(NFD)되어 오는 문제 |
| 제어 문자(Cc)와 서식 문자(Cf) 제거 | 개행은 로그 위조, RTLO(U+202E)는 `gpj.exe`를 `exe.jpg`처럼 보이게 하는 위장, 제로 폭 문자는 확장자 비교 우회 |
| 끝의 점과 공백 제거 | `file.exe.`, `file.exe ` 는 Windows에서 `file.exe`가 됨 |

정제 결과를 `original_name`에 저장합니다. 멀티파트 헤더에서 파일명은 **한 번만 추출**하고 이후 모든 단계가 그 값을 사용합니다(`filename`과 `filename*` 해석 차이로 검증과 저장이 다른 이름을 보는 문제 방지).

### 3-2. 파일명 유효성

| 조건 | 결과 |
|---|---|
| 정제 후 빈 문자열 | `INVALID_FILENAME` |
| 점으로만 구성 (`..`, `...`) | `INVALID_FILENAME` |
| UTF-8 255바이트 초과 (한글 약 85자, 영문 255자) | `INVALID_FILENAME`. 잘라내지 않고 거부 (잘라내다 확장자가 잘리면 검증 결과와 저장 이름이 달라짐) |
| 점으로 시작하는 이름이 254바이트 초과 | `INVALID_FILENAME`. 다운로드 이름에 `_`가 붙어(3-6) 255바이트를 넘기 때문 |
| 확장자(마지막 세그먼트)가 정규화 후 20자 초과 | `INVALID_FILENAME`. DB `file_upload.extension VARCHAR(20)`과 1:1 — 검증이 DB 길이보다 느슨하면 기록 저장이 실패해 요청 전체가 실패함 |

### 3-3. 세그먼트 규칙

파일명을 `.`으로 나눕니다.

| 경우 | 확장자 후보 |
|---|---|
| 일반 (`report.final.pdf`) | 첫 세그먼트(기본 이름)는 제외. 마지막 세그먼트가 확장자, 나머지는 중간 세그먼트 |
| 점으로 시작 (`.env`, `.exe`) | 첫 세그먼트도 포함. `.exe`는 `exe`가 확장자 후보 |
| 점 없음 (`README`, `backdoor`) | 확장자 없음 |
| 복합 (`a.tar.gz`) | 마지막 세그먼트 `gz`로 판정 |

첫 세그먼트를 제외하는 이유는 `com.example.config.txt`처럼 기본 이름이 고정 확장자(`com`)와 같은 정상 파일이 막히지 않게 하기 위해서입니다. 점 없는 파일명 전체를 확장자로 보지 않으므로 `readme`라는 커스텀 차단값이 있어도 `README` 파일은 막히지 않습니다.

### 3-4. 비교용 정규화

각 세그먼트를 비교할 때만 임시로 정규화하며, 저장 이름은 바꾸지 않습니다.

```
NFKC → 서식 문자(Cf) 제거 → 앞뒤 공백 제거 → 소문자(Locale.ROOT)
```

NFKC는 전각 `ｅｘｅ`를 `exe`로 바꾸는 등 표시를 바꾸므로 **비교용으로만** 쓰고, 저장용은 NFC입니다. `Locale.ROOT`는 터키어 로케일에서 `I`가 `ı`로 바뀌는 문제를 막습니다.

### 3-5. 블랙리스트 판정

| 조건 | 사유 코드 | 메시지 대상 |
|---|---|---|
| 마지막 세그먼트가 차단 대상 | `BLOCKED_EXTENSION` | 해당 확장자 |
| 중간 세그먼트가 차단 대상 | `BLOCKED_INNER_EXTENSION` | 어느 세그먼트 때문인지 표시 |

`my.js.notes.txt` 같은 정상 파일도 중간 세그먼트 `js` 때문에 막힐 수 있습니다. 오탐은 사용자가 파일명을 바꾸면 해결되지만 미탐은 되돌릴 수 없으므로 감수하고, 메시지에 원인 세그먼트를 알려 오탐 비용을 줄입니다.

### 3-6. 점 파일 이름 재부여

블랙리스트 검사가 **끝난 뒤** 점으로 시작하는 파일은 `download_name`을 `_` 접두어로 바꿉니다(`.env` → `_.env`). 저장은 어차피 UUID이므로 서버 쪽 위험(`.htaccess` 등)과는 무관하고, 다운로드한 사용자 PC에서 숨김 파일이 되는 것을 막기 위한 처리입니다. 업로드 결과에 이름이 바뀌었다는 안내를 포함합니다.

## 4. 확장자 정책 관리

### 4-1. 커스텀 확장자 입력 정규화

```
NFKC → 서식 문자(Cf) 제거 → 앞뒤 공백 제거 → 앞쪽 점 제거 → 소문자(Locale.ROOT) → ^[a-z0-9]{1,20}$ 검사
```

| 입력 | 처리 |
|---|---|
| `.sh`, `SH`, `ｓｈ` | 자동 보정해 `sh`로 저장, "sh로 저장되었습니다" 안내 |
| `s h`, `sh!`, `tar.gz` | 의도가 모호하므로 거부 |

20자 제한은 **정규화 이후** 값에 적용합니다(NFKC는 길이를 바꿀 수 있음). 클라이언트는 입력 단계에서 영숫자만 받아 즉시 피드백하고, 서버는 API 직접 호출에 대비해 같은 정규화를 다시 수행합니다. 이 정규화 함수는 업로드 판정(3-4)과 같은 구현을 공유합니다.

### 4-2. 추가·삭제·토글 규칙

| 상황 | 처리 |
|---|---|
| 커스텀 중복 (`sh` 두 번) | 409, "이미 등록된 확장자입니다" |
| 고정 확장자와 충돌 (커스텀에 `exe`) | 409, "exe는 고정 확장자입니다. 위 체크박스로 차단해 주세요" |
| 신뢰 목록 확장자 (커스텀에 `jpg`) | 허용. 판정 시 차단 우선 |
| 200개 도달 | 422, "삭제 후 추가할 수 있습니다". 고정 7개는 개수에 포함하지 않음 |
| 이미 없는 커스텀 삭제 | 204 (이미 원하는 상태이므로 성공) |
| 고정 토글 | 원하는 상태를 명시하는 멱등 API. 재시도해도 결과가 같음 |

중복·충돌은 `UNIQUE (policy_id, extension)`이 DB 레벨에서 함께 막습니다. 200개 제한은 "개수 조회 → 삽입" 사이 경쟁 조건이 있으므로 `pg_advisory_xact_lock(policy_id)`로 직렬화합니다. 커스텀 삭제는 실제로 지우며(hard delete), 이력은 `policy_change_log`가 보존합니다.

### 4-3. 동시 편집

`extension_rule.version`으로 낙관적 락을 겁니다. 화면이 본 버전과 현재 버전이 다르면 409로 거부하고 "다른 사용자가 먼저 변경했습니다. 새로고침 후 다시 시도해 주세요"를 표시합니다.

### 4-4. 변경 이력과 정책 버전

정책을 실제로 바꾼 경우에만, **같은 트랜잭션에서** `policy_change_log`에 한 행을 추가합니다. 수정·삭제 API는 두지 않습니다(append-only). 인증이 없으므로 행위자는 IP와 User-Agent로 기록합니다.

변경마다 반드시 행이 추가되므로 **정책 버전 = `MAX(policy_change_log.id)`** 입니다. 업로드 기록에는 정책 이름과 버전을 함께 남겨, 정책 변경 후 "옛 정책으로 통과한 파일"을 조회할 수 있게 합니다.

```sql
-- 예: exe 차단이 이력 id 42에서 켜졌다면, 그 전에 통과한 exe
SELECT * FROM file_upload
WHERE extension = 'exe' AND status = 'STORED' AND policy_version < 42;
```

## 5. 내용 검사

시그니처 판별은 **직접 작성한 시그니처 표**로 합니다. 문서를 해석하는 라이브러리(Tika parsers, PDFBox, POI)는 쓰지 않습니다. 신뢰할 수 없는 파일을 복잡한 파서에 넣으면 파서 자체가 공격 대상이 되기 때문입니다.

### 5-1. 실행 파일 시그니처 (모든 파일에 적용)

| 형식 | 시그니처 | 비고 |
|---|---|---|
| Windows PE (exe, scr, cpl, dll) | `4D 5A` ("MZ") + 오프셋 `0x3C`가 가리키는 위치에 `50 45 00 00` ("PE\0\0") | "MZ" 두 글자만 보면 "MZ세대.txt" 같은 텍스트가 오탐됨. PE 헤더 위치가 8KB 밖이면 보수적으로 거부 |
| ELF | `7F 45 4C 46` | 리눅스 실행 파일은 보통 확장자가 없어 이 검사가 사실상 유일한 판정 수단 |
| Mach-O | `FE ED FA CE`, `FE ED FA CF`, `CE FA ED FE`, `CF FA ED FE` | 32/64비트, 바이트 순서별 |
| Mach-O 유니버설 / Java 클래스 | `CA FE BA BE` | 두 형식이 같은 값을 씀. 둘 다 실행 가능하므로 차단 |
| 스크립트 | `23 21` ("#!") | 셔뱅이 있는 경우만 |

**시그니처로 판별할 수 없는 것**: `bat`, `cmd`, `js`, 셔뱅 없는 셸 스크립트(평문 텍스트), `com`(헤더 없는 형식), MSI(구형 doc/xls와 같은 OLE 형식이라 구분 불가). 이들은 확장자 정책과 저장·제공 방식(7장)이 방어합니다.

### 5-2. 신뢰 목록과 시그니처 (Java enum)

신뢰 목록은 DB가 아니라 Java enum `TrustedFileType`으로 관리합니다.

| 근거 | 내용 |
|---|---|
| 시그니처와 한 몸 | 시그니처는 어차피 탐지 코드에 있어야 하는 값입니다. 확장자·MIME·시그니처·리렌더링 방식을 한곳에 모으면, 목록과 검증 로직이 어긋날 수 없습니다 |
| 변경 통제 | 신뢰 부여는 inline 제공까지 허용하는 강한 결정입니다. 관리 화면에서 즉시 바꾸기보다 코드 리뷰와 테스트, 배포를 거치는 편이 안전합니다 |
| 단순함 | 테이블, 시드, 관리 API, 이력 처리가 모두 필요 없습니다 |

대가도 있습니다. 목록을 바꾸려면 재배포가 필요하고, 정책 세트(`upload_policy`)마다 다른 신뢰 목록을 둘 수 없습니다(모든 정책 세트가 같은 목록을 공유). 13장의 확장 방향에 영향을 줍니다.

| 확장자 | 분류 | 표준 MIME | 시그니처 | 저장 형식 | inline |
|---|---|---|---|---|---|
| jpg, jpeg | IMAGE | image/jpeg | `FF D8 FF` | JPEG 재인코딩 | 가능 |
| png | IMAGE | image/png | `89 50 4E 47 0D 0A 1A 0A` | PNG 재인코딩 | 가능 |
| gif | IMAGE | image/gif | `47 49 46 38` ("GIF8") | GIF 재인코딩 (첫 프레임) | 가능 |
| webp | IMAGE | image/webp | `52 49 46 46` + 오프셋 8에 `57 45 42 50` ("RIFF....WEBP") | **PNG로 재저장** | 가능 |
| pdf | DOCUMENT | application/pdf | `25 50 44 46 2D` ("%PDF-") | 원본 | 조건부 (5-4) |

Office 문서(docx, xlsx, pptx, 구형 doc/xls/ppt)와 hwp는 신뢰 목록에서 제외합니다. 구조가 복잡해 검사 비용과 파서 위험이 크고, 매크로 실행은 사용자 PC의 Office 보안 설정이 1차 방어를 맡습니다. 신뢰 목록에서 뺀다는 것은 "검사해서 안전하다"가 아니라 "안전하다고 보증하지 않는다"는 뜻입니다. SVG는 스크립트를 포함할 수 있어 제외합니다.

enum 구조 예시입니다. 시그니처는 (오프셋, 바이트) 목록이고, 모두 일치해야 해당 형식으로 판정합니다(webp처럼 두 위치를 봐야 하는 형식 대응).

```java
public enum TrustedFileType {
    JPG ("jpg",  Category.IMAGE,    "image/jpeg",      true, StoreAs.JPEG, sig(0, "FFD8FF")),
    JPEG("jpeg", Category.IMAGE,    "image/jpeg",      true, StoreAs.JPEG, sig(0, "FFD8FF")),
    PNG ("png",  Category.IMAGE,    "image/png",       true, StoreAs.PNG,  sig(0, "89504E470D0A1A0A")),
    GIF ("gif",  Category.IMAGE,    "image/gif",       true, StoreAs.GIF,  sig(0, "47494638")),
    WEBP("webp", Category.IMAGE,    "image/webp",      true, StoreAs.PNG,  sig(0, "52494646"), sig(8, "57454250")),
    PDF ("pdf",  Category.DOCUMENT, "application/pdf", true, StoreAs.ORIGINAL, sig(0, "255044462D"));

    // extension, category(크기 제한 분류), mime(탐지 비교 기준), inlineAllowed(형식 차원 최대치),
    // storeAs(리렌더링 결과 형식), signatures

    public static Optional<TrustedFileType> fromExtension(String normalizedExtension) { ... }
    public boolean matches(byte[] head) { ... }   // 모든 시그니처가 일치하는지
}
```

`inlineAllowed`는 형식 차원의 최대 허용치이고, 실제 제공 방식은 판정 시 파일마다 결정해 `file_upload.disposition`에 저장합니다(예: 스크립트가 있는 PDF는 attachment). 저장 시 실제 MIME은 `storeAs` 기준으로 `file_upload.content_type`에 저장합니다(webp → `image/png`).

### 5-3. 이미지 리렌더링

| 항목 | 규칙 |
|---|---|
| 픽셀 상한 | 5000만 픽셀. **디코딩 전에** 헤더에서 가로·세로만 읽어 검사 (디코딩 후에 세면 이미 메모리를 쓴 뒤). 초과 시 `SIZE_EXCEEDED` |
| 디코딩 실패 | 시그니처는 맞지만 이미지로 읽을 수 없으면 `CONTENT_MISMATCH` |
| 효과 | 폴리글랏 파일(뒷부분에 다른 형식을 붙인 파일)과 EXIF 위치 정보 등 메타데이터 제거 |
| 저장 | 리렌더링본을 저장. `sha256_original`(원본)과 `sha256_stored`(저장본) 모두 기록 |
| webp | Java 기본 라이브러리는 webp를 읽지 못하므로 읽기용 라이브러리 추가 필요 (예: TwelveMonkeys ImageIO). PNG로 재저장하므로 `content_type = image/png`, `download_name`의 확장자도 `.png`로 변경 |
| gif | 재인코딩 시 애니메이션은 첫 프레임만 남음. 폴리글랏 제거를 우선해 감수 |

### 5-4. PDF 검사

원본 바이트에서 이름 토큰을 검색합니다. PDF 객체 구조를 해석하지 않습니다.

| 키워드 | 의미 | 처리 |
|---|---|---|
| `/Launch` | 외부 프로그램 실행 | 거부 `ACTIVE_CONTENT` |
| `/EmbeddedFile` | PDF 안에 다른 파일 첨부 (내부 파일 검사 불가) | 거부 `ACTIVE_CONTENT` |
| `/JavaScript`, `/JS`, `/AA` | 스크립트, 동작 시 실행할 행동 | 저장, `attachment`로 낮춤 |
| `/Encrypt` | 암호화되어 내용 확인 불가 | 저장, `attachment`로 낮춤 |
| `/ObjStm` | 압축 객체 스트림 안에 키워드가 숨을 수 있어 확인 불가 | 저장, `attachment`로 낮춤 |
| `/OpenAction` 단독 | "열면 2페이지 표시" 같은 정상 PDF에서도 흔함 | 통과, 발견 사실만 로그 |
| 위 항목 없음 | — | 저장, `inline` |

거부와 낮춤의 기준은 **위험이 발생하는 시점**입니다. `attachment`는 브라우저에서 열리는 것만 막을 뿐 다운로드한 사용자가 PC에서 여는 것은 막지 못하므로, PC에서 열 때 위험한 항목(`/Launch`, `/EmbeddedFile`)은 거부합니다.

구현 시 주의할 점:

| 항목 | 내용 |
|---|---|
| 이름 인코딩 우회 | PDF 이름은 `#` + 16진수를 허용하므로 `/J#61vaScript` = `/JavaScript`. 검색 전에 이름 안의 `#xx`를 디코딩 |
| 토큰 경계 | `/JS`가 `/JSON`에 매칭되지 않도록 이름 뒤가 구분자(공백, `/`, `<`, `[`, `(` 등)인지 확인 |
| 검색 범위 | 파일 전체를 스트림으로 읽으며 검색. 메모리에 통째로 올리지 않음 |

### 5-5. 압축 파일 (zip)

zip은 비신뢰이지만, 압축 파일에 한해 내부 항목 검사를 추가로 거친 뒤 `attachment`로 저장합니다.

**판별 기준은 확장자입니다.** 시그니처(`PK`)로 판별하면 docx, xlsx, jar, apk까지 압축 파일 정책을 받게 되므로, 확장자가 `zip`인 파일만 압축 파일로 다룹니다. 확장자가 zip이 아닌 PK 시그니처 파일은 일반 비신뢰 파일로 처리합니다.

| 상황 | 처리 |
|---|---|
| zip 외 압축 형식 (`7z`, `rar`, `tar`, `gz`, `tgz`, `bz2`, `xz`) | 내부를 검사할 수 없으므로 거부 `ARCHIVE_UNSUPPORTED`. `.tar.gz`도 여기 해당 |
| 확장자는 zip인데 zip으로 읽을 수 없음 | 거부 `ARCHIVE_UNSUPPORTED` |
| 암호화된 항목 존재 (일반 목적 플래그 bit 0) | 거부 `ARCHIVE_ENCRYPTED` |
| 항목 100개 이상 | 거부 `ARCHIVE_LIMIT_EXCEEDED` |
| 해제 총량 200MB 초과 | 거부 `ARCHIVE_LIMIT_EXCEEDED` |
| 압축률 100:1 이상 (해제 총량 ÷ zip 크기) | 거부 `ARCHIVE_LIMIT_EXCEEDED` |
| 중첩 (내부 항목이 압축 파일) | 거부 `ARCHIVE_NESTED` |
| 내부 항목 이름이 차단 확장자 | 거부 `BLOCKED_EXTENSION` / `BLOCKED_INNER_EXTENSION` (메시지에 내부 항목 이름 표시) |
| 내부 항목이 실행 파일 시그니처 | 거부 `EXECUTABLE_DETECTED` |

구현 규칙:

| 항목 | 규칙 |
|---|---|
| 크기 측정 | zip 헤더에 적힌 크기는 조작 가능하므로 **실제로 읽은 바이트 수**로 셈. 상한을 넘는 순간 읽기 중단 |
| 해제 방식 | 디스크에 풀지 않고 메모리에서 스트림으로 읽음. 압축 해제 경로 조작(zip slip)이 성립하지 않음 |
| 내부 항목 이름 | 3장과 같은 정제·세그먼트·정규화 규칙 적용. 디렉터리 항목은 건너뜀 |
| 중첩 판정 | 내부 항목의 확장자가 압축 형식이거나, 앞부분이 zip/7z/rar/gzip 시그니처인 경우. 단 docx, xlsx, pptx, odt, ods, odp는 문서로 보고 중첩으로 판정하지 않으며 재귀 검사도 하지 않음 |

**한계**: 내부의 zip을 `.docx`로 이름을 바꿔 넣으면 중첩 판정과 재귀 검사를 피할 수 있습니다. 문서 파일과 압축 파일을 확실히 구분하려면 내부 구조를 해석해야 해서 파서 위험이 커지므로 감수합니다.

## 6. 크기·개수·요청 제한

| 항목 | 값 | 기준 / 위치 |
|---|---|---|
| 이미지 파일 | 10MB | **탐지된 형식** 기준 (확장자 기준이면 `.txt`를 붙여 우회 가능). DB `upload_policy` |
| 그 외 파일 | 25MB | DB `upload_policy` |
| 요청당 파일 수 | 10개 | DB `upload_policy` |
| 요청 전체 크기 | 100MB | DB `upload_policy` |
| 요청 수 제한 | 5분에 10회 | 설정 파일 |
| 이미지 픽셀 | 5000만 픽셀 | 설정 파일 |

크기 제한은 2단계로 적용합니다. 형식은 파일을 받은 뒤에야 알 수 있으므로, Spring 멀티파트 설정(`max-file-size` 100MB, `max-request-size` 100MB)으로 요청 전체 최대치를 먼저 끊고, 형식별 파일 제한은 탐지 후 애플리케이션에서 판정합니다. 멀티파트 `max-file-size`는 DB의 파일별 상한보다 **커야** 합니다 — 같으면 파일별 판정 전에 서블릿 단계에서 요청 전체가 거부되어 부분 성공과 메시지가 어긋납니다. 서블릿은 요청 전체 상한만 지키고, 파일별 상한은 파이프라인이 `SIZE_EXCEEDED`로 판정합니다. Spring은 크기 초과 시 컨트롤러 전에 `MaxUploadSizeExceededException`을 던지므로 전역 예외 처리에서 사유 코드 응답으로 변환합니다.

요청 수는 업로드 요청 1회를 1회로 셉니다(파일 수, 판정 결과와 무관). 집계는 `file_upload`에서 해당 IP의 최근 5분간 `request_id` 개수로 합니다.

## 7. 저장과 제공

| 항목 | 규칙 |
|---|---|
| 저장 키 | UUID, 확장자 없음. 원본 파일명은 DB에만 |
| 외부 식별자 | `public_id` (UUID). 순차 `id`는 노출하지 않음 (번호를 바꿔 남의 파일을 받는 IDOR 방지) |
| `Content-Type` | 서버가 판별한 값. 신뢰 파일은 형식의 MIME(리렌더링으로 형식이 바뀌면 바뀐 값), 비신뢰는 `application/octet-stream` |
| `Content-Disposition` | 신뢰 파일은 판정에 따라 `inline` 또는 `attachment`, 비신뢰는 항상 `attachment` (DB 제약으로 강제) |
| 공통 헤더 | `X-Content-Type-Options: nosniff` |
| 다운로드 파일명 | 한글 파일명은 RFC 5987 인코딩 (`filename*=UTF-8''...`) |
| 화면 표시 | 파일명이 표시되는 모든 곳(결과 목록, 차단 메시지 등)에서 HTML 이스케이프. 파일명 `<img src=x onerror=...>.jpg` 대비 |
| 업로드 경로 | 반드시 서버를 거쳐 S3에 저장 (클라이언트 직접 업로드는 서버 검증을 건너뜀) |

S3 버킷 설정, 다운로드 URL 방식, inline 파일 제공 도메인은 미결입니다(16장).

## 8. 반복 위반 IP 일시 차단

거부 기록을 활용해, 우회를 탐색하는 반복 시도를 억제합니다. 검증 자체를 강화하는 기능은 아니며, IP를 바꾸면 우회되는 보조 수단입니다.

### 8-1. 위반 점수

정상 사용자의 실수와 의도적인 위장을 구분하기 위해 사유별로 점수를 다르게 둡니다. 점수는 판정 시점에 계산해 `file_upload.violation_score`에 저장하므로, 나중에 가중치를 바꿔도 과거 기록의 의미가 바뀌지 않습니다.

| 사유 코드 | 점수 | 근거 |
|---|---|---|
| `EXECUTABLE_DETECTED` | 3 | 확장자 없는 ELF, zip 속 실행 파일 등. 의도 가능성 높음 |
| `CONTENT_MISMATCH` | 3 | 위장은 실수로 생기지 않음 |
| `ACTIVE_CONTENT` | 2 | 조작된 PDF 가능성 |
| `ARCHIVE_NESTED` | 1 | 우회 시도일 수 있으나 정상 백업 파일도 해당 |
| `ARCHIVE_LIMIT_EXCEEDED` | 1 | 압축 폭탄 가능성. 반복 로그처럼 압축률 높은 정상 파일도 있음 |
| `BLOCKED_EXTENSION`, `BLOCKED_INNER_EXTENSION` | 0 | 정책을 몰라서 흔히 발생. 부분 성공 방식에서 한 요청으로 차단되는 문제 방지 |
| `INVALID_FILENAME`, `SIZE_EXCEEDED`, `ARCHIVE_ENCRYPTED`, `ARCHIVE_UNSUPPORTED` | 0 | 의도와 무관 |

### 8-2. 차단 규칙

| 항목 | 값 |
|---|---|
| 집계 창 | 최근 10분 |
| 임곗값 | 점수 합 6점 이상 (위장 시도 2회) |
| 차단 시간 | 5분 (영구 차단 없음, 시간이 지나면 자동 해제) |
| 확인 위치 | 서블릿 필터. 멀티파트 본문을 읽기 전에 거부 |
| 기록 | `ip_block` 테이블. 차단 시점의 누적 점수 저장 |
| 수동 해제 | 관리 화면에서 해제. `released_at`, `released_by_ip` 기록 |
| 메시지 | "반복된 정책 위반으로 업로드가 일시 제한되었습니다. (약 N분 후 해제)" — N은 남은 시간. 점수 기준은 공개하지 않음 |

한계: 회사·학교·통신사처럼 여러 사람이 같은 공인 IP를 쓰면 한 사람 때문에 함께 차단됩니다. 짧은 차단 시간과 수동 해제로 완화합니다.

## 9. 사유 코드와 메시지

서버는 사유 코드를 내려주고, 화면은 코드에 맞는 문구를 표시합니다. 탐지 방식의 상세(예: "MZ 헤더 감지")는 사용자에게 보여주지 않고 로그에만 남깁니다.

### 9-1. 파일 단위 (`file_upload`에 기록)

| 코드 | 메시지 예시 |
|---|---|
| `BLOCKED_EXTENSION` | setup.exe — exe 파일은 보안 정책상 업로드할 수 없습니다. |
| `BLOCKED_INNER_EXTENSION` | app.js.txt — 파일명 중간의 .js가 차단 대상입니다. 파일명을 확인해 주세요. |
| `EXECUTABLE_DETECTED` | backdoor — 실행 파일은 업로드할 수 없습니다. |
| `CONTENT_MISMATCH` | report.jpg — 파일 내용이 확장자와 일치하지 않습니다. |
| `ACTIVE_CONTENT` | manual.pdf — 문서에 외부 실행이나 첨부 파일 등 실행 가능한 요소가 포함되어 업로드할 수 없습니다. |
| `SIZE_EXCEEDED` | photo.jpg — 이미지 파일은 10MB를 넘을 수 없습니다. (현재 23.4MB) / 이미지 해상도가 허용 범위를 넘습니다. |
| `INVALID_FILENAME` | 파일 이름이 비어 있거나 너무 깁니다. (최대 255바이트) |
| `ARCHIVE_NESTED` | backup.zip — 압축 파일 안에 다른 압축 파일이 있어 업로드할 수 없습니다. |
| `ARCHIVE_LIMIT_EXCEEDED` | data.zip — 압축 파일의 항목 수 또는 해제 크기가 허용 범위를 넘습니다. |
| `ARCHIVE_ENCRYPTED` | secret.zip — 암호가 걸린 압축 파일은 내용을 확인할 수 없어 업로드할 수 없습니다. |
| `ARCHIVE_UNSUPPORTED` | files.7z — zip 외의 압축 형식은 업로드할 수 없습니다. |

차단이 아닌 안내도 결과에 포함합니다: 점 파일 이름 재부여(`.env` → `_.env`), webp의 PNG 변환, PDF의 `attachment` 제공.

### 9-2. 요청 단위 (로그에만 기록)

| 코드 | HTTP | 메시지 예시 |
|---|---|---|
| `TEMPORARILY_BLOCKED` | 429 + `Retry-After` | 반복된 정책 위반으로 업로드가 일시 제한되었습니다. (약 5분 후 해제) |
| `RATE_LIMITED` | 429 + `Retry-After` | 요청이 너무 많습니다. 잠시 후 다시 시도해 주세요. |
| `REQUEST_TOO_LARGE` | 413 | 한 번에 올릴 수 있는 전체 크기는 100MB입니다. |
| `TOO_MANY_FILES` | 400 | 한 번에 최대 10개까지 올릴 수 있습니다. |
| `NO_FILES` | 400 | 업로드할 파일이 없습니다. (`files` 파트 없음, 멀티파트가 아닌 요청) |

## 12. 인증

회원·인증은 도입하지 않습니다. 과제 요구사항에 없고, 면접 당일 누구나 접속해 시연할 수 있어야 하기 때문입니다.

| 항목 | 규칙 |
|---|---|
| API 분리 | 정책 관리는 `/api/admin/**`, 업로드는 `/api/uploads/**`. 인증 도입 시 경로 단위로 권한 적용 |
| 행위자 식별 | IP 기반 (의미는 16장 미결 사항 참고) |
| 요청자 정보 | `ActorResolver` 한 곳에서 생성. 인증 도입 시 이 구현만 교체 |
| 업로드 목록 | 전체 업로드 파일 목록과 다운로드 링크를 공개하지 않음 (누구나 남의 파일을 받는 공개 게시판이 되는 것 방지) |

## 13. 향후 확장

| 방향 | 현재 대비 |

| 사용자별 정책 | 정책 세트(`upload_policy`)에 고유 이름 부여. 회원 도입 시 회원 ↔ 정책 매핑. 크기·개수·차단 목록은 정책 세트 단위, 신뢰 목록은 enum이라 전체 공통 |

## 15. 데이터 모델 요약

상세 정의(컬럼, 제약, 인덱스, 시드)는 `schema.sql`을 따릅니다.

| 테이블 | 역할 | 핵심 제약 |
|---|---|---|
| `upload_policy` | 정책 세트 (이름, 크기·개수 제한) | 이름 UNIQUE |
| `extension_rule` | 차단 목록 (고정 7 + 커스텀 ≤200) | `UNIQUE(policy_id, extension)`, 정규화 형식 CHECK, 커스텀은 항상 차단 |
| `policy_change_log` | 정책 변경 이력, id = 정책 버전 | append-only |
| `file_upload` | 파일별 판정 기록 (허용·거부 모두) | 거부면 사유 필수, 저장이면 저장 키·해시 2개·MIME·제공 방식 필수, 비신뢰는 attachment만 |
| `ip_block` | 반복 위반 IP 일시 차단 | 차단 기간 역전 방지 |

신뢰 목록은 테이블이 아니라 Java enum `TrustedFileType`입니다(5-2).

이력과 업로드 기록은 정책 행에 FK를 걸지 않고 확장자 문자열을 그대로 저장합니다. 커스텀 확장자를 삭제해도 과거 기록이 남아야 하기 때문입니다.

### API 초안

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/admin/policies` | 고정·커스텀 목록, 개수, 각 행의 version |
| PUT | `/api/admin/policies/fixed/{ext}` | 본문 `{ "blocked": true, "version": 3 }`. 멱등. 버전 불일치 시 409 |
| POST | `/api/admin/policies/custom` | 본문 `{ "extension": ".SH" }`. 정규화 결과와 보정 여부 반환 |
| DELETE | `/api/admin/policies/custom/{ext}` | 없어도 204 |
| GET | `/api/admin/ip-blocks` | 활성 차단 목록 |
| DELETE | `/api/admin/ip-blocks/{id}` | 수동 해제 |
| POST | `/api/uploads` | 멀티파트. 파일별 결과 반환 |
| GET | `/api/uploads/{publicId}` | 다운로드 (방식은 S3 미결 사항에 따름) |

에러 응답 형식:

```json
{ "code": "CUSTOM_LIMIT_EXCEEDED", "message": "삭제 후 추가할 수 있습니다.", "detail": { "current": 200, "max": 200 } }
```

업로드 응답 형식:

```json
{
  "requestId": "2f1c...",
  "results": [
    { "fileName": "cat.webp", "status": "STORED", "publicId": "9a3e...",
      "disposition": "INLINE", "notices": ["PNG로 변환되어 저장되었습니다."] },
    { "fileName": "report.jpg", "status": "REJECTED", "reasonCode": "CONTENT_MISMATCH",
      "message": "report.jpg — 파일 내용이 확장자와 일치하지 않습니다." }
  ]
}
```

**공통 클라이언트 오류 코드** — 어느 API에서나 올 수 있고, 같은 형식으로 응답합니다. 서버 오류(500)로 위장하지 않습니다.

| 코드 | HTTP | 상황 |
|---|---|---|
| `INVALID_REQUEST` | 400 | 본문 검증 실패(`detail`에 필드별 메시지), 깨진 JSON, 타입 불일치(UUID가 아닌 id), 필수 파라미터 누락 |
| `NOT_FOUND` | 404 | 없는 경로 (리소스가 없는 경우는 각 API의 `NOT_FOUND`) |
| `METHOD_NOT_ALLOWED` | 405 | 허용되지 않은 메서드 |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | 지원하지 않는 Content-Type |
| `INTERNAL_ERROR` | 500 | 그 외 예외. ERROR 로그와 함께 |

## 16. 미결 사항

| 항목 | 상태 |
|---|---|
| S3 세부 (버킷 접근 설정, 다운로드 URL 방식, inline 파일 제공 도메인) | 별도 전달 예정 |

검토했으나 이번 범위에서 제외한 항목입니다. `CONSIDERATIONS.md`에는 제외 근거를 함께 적어야 합니다.

| 항목 | 비고 |
|---|---|
| 프록시 뒤 실제 클라이언트 IP 판별 | IP 기반 기능(요청 수 제한, IP 차단, 이력) 전체에 영향 |
| IP 보관 기간·마스킹 | 이력은 영구 보관 |
| 업로드 파일 보관 기간 | 자동 삭제 없음 |
| 고정 확장자 기본값 unCheck와 보안 기본값의 긴장 | 요구사항대로 unCheck. 실행 파일 시그니처 검사가 최소 방어선 |
| 면접 시연 대비 (정책 초기화, 콜드 스타트, 샘플 파일) | — |
| Office 문서·hwp 내용 검사, DRM 문서 탐지 | 신뢰 목록 제외로 대체 |

## 17. 알려진 한계

| 한계 | 대응 |
|---|---|
| `bat`, `cmd`, `js`, `com`, 셔뱅 없는 스크립트는 시그니처로 판별 불가 | 확장자 정책 + `octet-stream` / `attachment` / `nosniff` |

| Office 문서의 매크로·DDE·원격 템플릿은 검사하지 않음 | 비신뢰 attachment. 사용자 PC의 Office 보안 설정에 의존 |

| zip 속 압축 파일을 문서 확장자로 위장하면 재귀 검사 회피 | 감수 (파서 위험과의 균형) |
| IP 차단은 IP 변경으로 우회 가능, 공유 IP는 함께 차단 | 보조 수단으로 한정, 짧은 차단 시간, 수동 해제 |

## 18. 구현 순서와 핵심 테스트

### 구현 순서

1. 스키마 적용과 정책 관리 API·화면 (고정 토글, 커스텀 추가·삭제, 개수 표시)
2. 업로드 API: 파일명 처리, 블랙리스트 강제, 사유 코드 응답 (필수 범위 완성)
3. 실행 파일 시그니처, 신뢰 목록 enum과 시그니처 검사
4. 이미지 리렌더링, PDF 검사, zip 검사
5. 요청 단위 필터 (IP 차단, 요청 수 제한), 위반 점수
6. S3 연동과 배포
7. 테스트 보강, 문서 3종 정리

### 핵심 테스트 케이스

| 입력 | 기대 결과 |
|---|---|
| `setup.EXE` (exe 차단 중) | `BLOCKED_EXTENSION` |
