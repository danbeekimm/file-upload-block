### 2-2. 패키지 (`com.study.fileupload`)

패키지는 레이어가 아니라 **기능 단위**다. 한 패키지 안에 컨트롤러·서비스·엔티티·리포지토리가 함께 있다.

| 패키지 | 책임 | 클래스 |
|---|---|---|
| `policy` | 차단 확장자 정책 관리 | `AdminPolicyController`(API) · `PolicyService`(토글/추가/삭제/스냅샷) · `UploadPolicy`, `ExtensionRule`, `PolicyChangeLog`(엔티티) · `PolicyRepositories`(패키지 전용 리포지토리 3개) · `PolicySnapshot`, `PolicyView`(값 객체) |
| `upload` | 업로드 판정 파이프라인, 다운로드 | `UploadController` · `UploadService`(파이프라인) · `FilenameProcessor`, `FilenameInfo`(파일명) · `TrustedFileType`(신뢰 목록 enum) · `ExecutableSignatureDetector`, `ImageReRenderer`, `PdfInspector`, `ZipInspector`(내용 검사) · `FileUploadRecord`, `FileUploadRepository`(판정 기록) · `RejectException`, `UploadResponse` |
| `guard` | 요청 단위 방어, IP 차단 | `UploadGuardFilter`(서블릿 필터) · `IpBlockService` · `IpBlock`, `IpBlockRepository` · `IpBlockAdminController` |
| `storage` | 객체 저장소 | `ObjectStorage`(인터페이스) · `LocalObjectStorage` · `S3ObjectStorage` · `StorageConfig`(모드 선택, S3 자격 증명) |
| `common` | 공용 타입 | `ReasonCode`(거부 사유 + 위반 점수) · `ApiException`, `ErrorResponse`, `GlobalExceptionHandler` · `Actor`, `ActorResolver`(요청자) · `ExtensionNormalizer`(정규화) |
| `config` | yml 바인딩 | `UploadProperties`(`upload.*`) · `StorageProperties`(`storage.*`) |
| `web` | 페이지 | `PageController` (`GET /` → `index.html`) |

### 2-3. 패키지 간 참조

```
web      → (없음)
policy   → common
guard    → policy(기본 정책 상한), upload(FileUploadRepository 집계), config, common
upload   → policy(스냅샷), guard(IpBlockService.evaluate), storage, config, common
storage  → config
```

`upload`와 `guard`는 서로를 참조한다. 업로드 서비스는 판정이 끝난 뒤 차단 평가를 호출하고, 가드는 요청 수·위반 점수 집계를 위해 업로드 기록 리포지토리를 쓴다. 빈 생성 순환은 없다 (`UploadService → IpBlockService → FileUploadRepository`).

### 2-4. 두 종류의 코드

| 종류 | 대상 | 특징 |
|---|---|---|
| Spring 빈 | 컨트롤러, 서비스, 필터, 리포지토리, `StorageConfig`, `ActorResolver` | 트랜잭션·DB·HTTP를 다룬다 |
| 정적 유틸리티 | `FilenameProcessor`, `ExtensionNormalizer`, `ExecutableSignatureDetector`, `PdfInspector`, `ZipInspector`, `ImageReRenderer`, `TrustedFileType` | Spring 의존 없음. 설정은 인자로 받는다 (`ZipInspector.Config`, `maxPixels`). 단위 테스트 67개가 이 계층을 컨텍스트 없이 검증한다 |

| 멀티파트 상한 | `application.yml` `spring.servlet.multipart` | 파일 100MB · 요청 100MB (파일별 상한은 정책이 판정하므로 정책 값보다 커야 함) |

| DB 접속 | `application.yml` `spring.datasource` | `DB_HOST`/`DB_PORT`/`DB_NAME`/`DB_USER`/`DB_PASSWORD` (기본 localhost:55432/fileupload) |

## 4. 처리 흐름

### 4-1. 정책 관리 (`/api/admin/policies`)

| 요청 | 흐름 | 응답 |
|---|---|---|
| `GET` | `PolicyService.view` — 고정은 `FIXED_ORDER` 순서, 커스텀은 생성순 | `{fixed[{extension,blocked,version}], custom[{extension}], customCount, customMax}` |
| `PUT /fixed/{ext}` `{blocked, version}` | 입력 정규화 → FIXED 행 조회(없으면 404) → 클라이언트 `version`과 행의 `version` 비교(다르면 409 `VERSION_CONFLICT`) → 상태가 다를 때만 `toggle()`(version+1) + `policy_change_log` BLOCK/UNBLOCK | 변경 후 `{extension,blocked,version}`. 같은 상태 요청은 변경 없이 200 (멱등) |
| `POST /custom` `{extension}` | 정규화(실패 400 `INVALID_EXTENSION`) → `pg_advisory_xact_lock(policy_id)` → 같은 확장자 존재 시 409 (`FIXED_CONFLICT` / `DUPLICATE_EXTENSION`) → 200개면 422 `CUSTOM_LIMIT_EXCEEDED` → `save`+`flush`(UNIQUE 위반이면 409) → `policy_change_log` ADD | 201 `{extension, corrected, count, max}` |
| `DELETE /custom/{ext}` | 정규화 실패·행 없음·고정 행 → 아무것도 안 함. 커스텀 행이면 삭제 + `policy_change_log` DELETE | 항상 204 (멱등) |

- **정규화** (`ExtensionNormalizer.normalizeCustomInput`): NFKC → 서식 문자 제거 → 공백 제거 → 앞쪽 점 제거 → 소문자 → `^[a-z0-9]{1,20}$` 검사. DB의 `ck_extension_rule_format`과 같은 패턴이다.
- **정책 버전**: `policy_change_log`의 `MAX(id)`. 변경이 실제로 일어난 경우에만 행이 추가되므로 별도 버전 테이블이 없다.
- **고정 토글의 낙관적 락**: JPA `@Version`이 아니라 서비스가 직접 비교·증가한다. "클라이언트가 본 버전"과 비교한다는 의미를 그대로 두기 위해서다.
- 모든 변경에 `Actor`(IP, User-Agent)가 이력에 남는다.

### 4-2. 업로드 (`POST /api/uploads`, 멀티파트 `files`)

업로드 한 건은 네 단계를 지난다.

**A. 요청 단위 — 서블릿 필터** (`UploadGuardFilter`, 멀티파트 본문을 읽기 전)

| 순서 | 검사 | 근거 데이터 | 거부 |
|---|---|---|---|
| 1 | 활성 IP 차단 | `ip_block` (해제 안 됨 + 기간 남음) | 429 `TEMPORARILY_BLOCKED` + `Retry-After`(남은 초) |
| 2 | 요청 수 제한 | `file_upload`에서 최근 5분 `COUNT(DISTINCT request_id)` | 429 `RATE_LIMITED` + `Retry-After` |
| 3 | 요청 전체 크기 | `Content-Length` vs 정책 `max_request_bytes` | 413 `REQUEST_TOO_LARGE` |

요청 단위 거부는 `file_upload`에 기록하지 않고 로그만 남긴다. 필터는 MVC 밖이므로 `ErrorResponse` JSON을 직접 쓴다.

**B. 요청 단위 — 서비스 진입** (`UploadService.process`)

1. `PolicyService.snapshot()` — 정책 행 + 차단 확장자 집합 + 정책 버전을 한 번에 읽는다. 요청 안의 모든 파일이 같은 스냅샷으로 판정된다.
2. 파일이 없으면 400 `NO_FILES`, 개수가 정책 상한을 넘으면 400 `TOO_MANY_FILES` (요청 전체 거부, 로그만).
3. `requestId`(UUID) 발급. 파일마다 `judgeAndRecord` 호출.

**C. 파일 단위 — 판정 파이프라인** (`judgeAndRecord`, 파일별 독립 판정 = 부분 성공)

| 단계 | 수행 | 거부 코드 (점수) |
|---|---|---|
| 1 | `FilenameProcessor.sanitize`: 경로 제거 → NFC → 제어·서식 문자 제거 → 끝의 점·공백 제거. 이후 모든 단계가 이 값을 쓴다 | — |
| 2 | `validate`: 빈 이름, 점만 있는 이름, UTF-8 255바이트 초과(점 파일은 254), 확장자 20자 초과 | `INVALID_FILENAME` (0) |
| 3 | `parse` 후 마지막 세그먼트가 스냅샷의 차단 집합에 있는가 | `BLOCKED_EXTENSION` (0) |
| 4 | 중간 세그먼트(첫 세그먼트 제외)가 차단 집합에 있는가 | `BLOCKED_INNER_EXTENSION` (0) |
| 5 | 앞부분 8KB 읽기 (`upload.inspect.head-bytes`) | — |
| 6 | `ExecutableSignatureDetector`: PE(MZ + e_lfanew → `PE\0\0`), ELF, Mach-O, `CAFEBABE`, 셔뱅. 모든 파일에 적용 | `EXECUTABLE_DETECTED` (3) |
| 7 | 확장자가 신뢰 목록이면 시그니처 일치 확인. zip 외 압축 확장자(7z rar tar gz tgz bz2 xz)는 거부 | `CONTENT_MISMATCH` (3) · `ARCHIVE_UNSUPPORTED` (0) |
| 8 | 탐지된 형식 기준 크기 검사 — 이미지면 `max_image_bytes`, 아니면 `max_file_bytes` | `SIZE_EXCEEDED` (0) |
| 9 | 원본 SHA-256 계산, `detected_type` 결정, 클라이언트 MIME 불일치는 로그만 | — |
| 10 | 형식별 내용 검사 → 분류 (아래 표) | `ACTIVE_CONTENT` (2) · `ARCHIVE_*` |
| 11 | 저장 + 기록 | — |

**10단계의 형식별 분기** (`storeAndRecord`)

| 분류 | 조건 | 처리 | 저장 Content-Type | 제공 |
|---|---|---|---|---|
| 신뢰 이미지 | `TrustedFileType` IMAGE (jpg jpeg png gif webp) | 헤더의 가로×세로로 픽셀 상한 검사 → 디코딩 → 재인코딩 (메타데이터·폴리글랏 꼬리 제거). webp는 PNG로 재저장 | 형식의 MIME | `INLINE` |
| 신뢰 문서 | PDF | `PdfInspector`: 바이트에서 이름 토큰 검색 (`#xx` 디코딩, 토큰 경계). `/Launch` `/EmbeddedFile(s)` → 거부, `/JavaScript` `/JS` `/AA` `/Encrypt` `/ObjStm` → attachment로 강등, `/OpenAction` → 로그만 | `application/pdf` | `INLINE` 또는 `ATTACHMENT` |
| zip | 확장자 `zip` + PK 시그니처 | `ZipInspector`: 스트림으로만 읽음. 항목마다 이름(차단 확장자·중간 세그먼트) → 내용(실행 시그니처, 중첩 압축) → 실제 읽은 바이트로 크기·항목 수·압축률 검사. 암호화 비트면 거부 | `application/octet-stream` | `ATTACHMENT` |
| 비신뢰 | 그 외 전부 (txt, docx, hwp, 무확장자 …) | 추가 검사 없음 | `application/octet-stream` | `ATTACHMENT` |

**11단계 저장·기록**

1. 점으로 시작하는 이름은 다운로드 이름을 `_` 접두어로 바꾼다 (`.env` → `_.env`). 블랙리스트 검사가 끝난 뒤에 적용.
2. 저장 키는 확장자 없는 UUID. 리렌더링한 이미지는 결과 바이트를, 그 외는 원본 스트림을 `ObjectStorage.put`.
3. `file_upload`에 STORED 행 저장 (원본 이름, 다운로드 이름, 확장자, 크기, 원본/저장 해시, 신뢰 수준, Content-Type, 제공 방식, 저장 키, 정책 버전, IP). DB 저장이 실패하면 방금 올린 객체를 삭제하고 예외를 다시 던진다.
4. 응답 항목 `{fileName, status: STORED, publicId, disposition, notices}`.

**거부 처리**: 파이프라인 어디서든 `RejectException`을 던지면 `judgeAndRecord`의 catch가 받아 INFO 로그 + `file_upload`에 REJECTED 행(사유 코드, 그 시점의 위반 점수, 정책 버전) 저장 + 응답 항목 `{fileName, status: REJECTED, reasonCode, message}`. 응답 메시지는 사용자용이고, 시그니처 이름 같은 상세는 로그에만 간다 (`RejectException.logDetail`). 의심 신호는 WARN + `[SUSPICIOUS]` 접두어다.

**D. 요청 마무리** — 모든 파일 처리 후 `IpBlockService.evaluate(ip)` (4-4). 응답 `{requestId, results[]}`.

### 4-3. 다운로드 (`GET /api/uploads/{publicId}`)

1. `public_id`로 조회, `STORED`만 (아니면 404 `NOT_FOUND`).
2. `ObjectStorage.get(storage_key)` 스트림을 그대로 흘린다.
3. 헤더는 판정 때 저장한 값: `Content-Type` = `content_type`, `Content-Disposition` = `disposition`(inline/attachment) + `download_name`(RFC 5987 UTF-8), `X-Content-Type-Options: nosniff` 항상.

### 4-4. 반복 위반 IP 차단

| 단계 | 내용 |
|---|---|
| 점수 | 거부 사유마다 `ReasonCode`에 고정: `EXECUTABLE_DETECTED` 3 · `CONTENT_MISMATCH` 3 · `ACTIVE_CONTENT` 2 · `ARCHIVE_NESTED` 1 · `ARCHIVE_LIMIT_EXCEEDED` 1 · 나머지 0. 판정 시점 값을 `file_upload.violation_score`에 복사 |
| 평가 | 요청의 파일 판정이 모두 끝난 뒤. 활성 차단이 없고, 최근 10분 점수 합이 6 이상이면 `ip_block` 행 생성 (5분) + WARN 로그 |
| 적용 | 다음 요청부터 `UploadGuardFilter` 1번 검사에서 429 |
| 해제 | 기간 만료로 자동. 또는 `DELETE /api/admin/ip-blocks/{id}` → `released_at`/`released_by_ip` 기록 (행은 남는다) |
| 조회 | `GET /api/admin/ip-blocks` — 활성 차단 목록 |

### 4-5. 오류 응답 형식

| 출처 | 처리 | 형식 |
|---|---|---|
| 서비스의 `ApiException` | `GlobalExceptionHandler.handleApi` | 지정한 상태 코드 + `{code, message, detail?}` |
| 본문 검증 실패 (`@Valid`) | `handleValidation` | 400 `INVALID_REQUEST` + 필드별 detail |
| 깨진 JSON, 타입 불일치(UUID 아닌 id), 파라미터 누락 | `handleBadRequest` | 400 `INVALID_REQUEST` |
| `files` 파트 없음, 멀티파트 아님 | `handleNoFiles` | 400 `NO_FILES` |
| 없는 경로 / 허용되지 않은 메서드 / Content-Type | `handleNotFound` 등 | 404 `NOT_FOUND` / 405 `METHOD_NOT_ALLOWED` / 415 |
| 멀티파트 요청 상한 초과 (`MaxUploadSizeExceededException`) | `handleTooLarge` | 413 `REQUEST_TOO_LARGE` (상한은 설정값에서) |
| 그 외 모든 예외 | `handleUnexpected` | 500 `INTERNAL_ERROR` + ERROR 로그 |
| 필터 단계 거부 | 필터가 직접 JSON 작성 | 429/413 + `{code, message}` |

## 5. 데이터 모델

| 테이블 | 엔티티 | 역할 | 핵심 |
|---|---|---|---|
| `upload_policy` | `UploadPolicy` | 정책 세트 (현재 `default` 하나) | 크기·개수 제한 보유. 엔티티는 읽기 전용 |
| `extension_rule` | `ExtensionRule` | 차단 목록 | `UNIQUE(policy_id, extension)` · FIXED는 `blocked` 토글 + `version`, CUSTOM은 행 존재 = 차단 |
| `policy_change_log` | `PolicyChangeLog` | 정책 변경 이력 (append-only) | `MAX(id)` = 정책 버전 · `detail` jsonb · 행위자 IP/UA |
| `file_upload` | `FileUploadRecord` | 파일별 판정 기록 (허용·거부 모두) | `public_id`(외부 식별자) · `request_id`(요청 묶음) · `policy_version` · `violation_score` · 해시 2종 · 저장 키 |
| `ip_block` | `IpBlock` | 일시 차단 | `blocked_until` · 수동 해제 컬럼. 행 자체가 이력 |

- 이력·기록 테이블은 정책 행에 FK를 걸지 않고 확장자 문자열을 복사한다. 커스텀을 삭제해도 과거 기록이 남는다.
- 상태값(`status`, `reject_reason`, `trust_level`, `disposition`)은 DB CHECK로 고정되어 있고, `ReasonCode` enum과 1:1이다.
- 집계 쿼리는 `FileUploadRepository`에 있다: 요청 수(`countRecentRequests`), 위반 점수 합(`sumRecentViolationScore`). 인덱스 `(client_ip, created_at)`.

## 6. 저장소

| 구현 | 선택 조건 | 동작 |
|---|---|---|
| `LocalObjectStorage` | `storage.mode=local` (기본) | `STORAGE_DIR`(기본 `./data/objects`) 아래 UUID 파일. 키의 경로 이탈을 방어적으로 차단 |
| `S3ObjectStorage` | `storage.mode=s3` | `prefix + key`로 put/get/delete. `S3Exception`은 `IOException`으로 바꿔 파이프라인에 전달 |

선택과 S3 클라이언트 생성은 `StorageConfig.objectStorage` 빈 한 곳에서 한다. 키에 확장자가 없고 원본 이름은 DB에만 있으므로, 저장소 URL로 직접 접근·실행될 수 없고 제공은 항상 4-3을 거친다.

## 7. 화면 (`index.html`)

Thymeleaf 템플릿 한 장이지만 서버 측 치환은 없고, 바닐라 JS가 API를 호출한다.

| 영역 | 동작 | API |
|---|---|---|
| 고정 확장자 | 체크박스 7개. 바꾸면 현재 `version`을 함께 보내고, 응답의 `version`으로 갱신. 409면 메시지 표시 | `GET`, `PUT /fixed/{ext}` |
| 커스텀 확장자 | 입력(20자 카운터) + 추가 버튼 + 칩 목록(삭제 ×). 보정 저장 시 안내 | `POST /custom`, `DELETE /custom/{ext}` |
| 파일 업로드 | 다중 선택 → XHR로 전송(진행률 `<progress>`) → 파일별 결과 목록(STORED/REJECTED + 사유·안내) | `POST /api/uploads` |
